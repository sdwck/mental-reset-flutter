# Шпаргалка к защите L4 (Mental Reset)

**Что сделано одной фразой:** дневник сессий осознанности теперь живёт в общей модели `SessionsModel` (ChangeNotifier + Provider), данные идут через интерфейс `SessionRepository` с mock-реализацией (задержка 700 мс + переключаемая авария), каждый экран с данными показывает загрузку / данные / ошибку с кнопкой «Повторить», форма «Новая сессия» сохраняет через репозиторий, и Дневник с Профилем обновляются сами.

## Вопросы, которые точно спросят

**1. Эфемерное vs разделяемое состояние?**
Эфемерное нужно одному виджету (выбранный звук на «Звуках», флаг `_saving` в форме) → `setState`. Разделяемое нужно нескольким экранам (список сессий: Дневник, Детали, Профиль) → `ChangeNotifier` + `Provider`.

**2. Почему коллекция read-only?**
`items` отдаёт `UnmodifiableListView`. Снаружи список не изменить, менять можно только методами модели (`add`, `edit`, `remove`), а они всегда зовут `notifyListeners()`. Иначе кто-то поменяет список «втихую», и UI не узнает.

**3. watch / read / Consumer — в чём разница?**
- `context.watch<T>()` — в `build`, подписывается: экран перестраивается при `notifyListeners()` (Дневник).
- `context.read<T>()` — в обработчиках (onPressed, onRetry, submit): просто взять модель и вызвать метод, без подписки. В build read не используем, иначе экран не обновится.
- `Consumer<T>` — перестраивает только кусок дерева (карточка статистики в Профиле).
- `context.select` — подписка на одно поле (Детали следят только за своей сессией).

**4. Что такое Result и зачем sealed?**
`sealed class Result<T>` с двумя наследниками `Ok(value)` и `Err(message)`. Репозиторий никогда не бросает исключение наружу, а возвращает Result. Благодаря `sealed` в `switch` компилятор заставляет обработать оба случая.

**5. Зачем интерфейс репозитория и внедрение через конструктор?**
`SessionsModel(this._repo)` знает только интерфейс `SessionRepository`. Какую реализацию дать, решает один файл, `main.dart` (корень композиции). На L5 там `MockSessionRepository` заменится на `HttpSessionRepository`, а экраны и модели не поменяются ни строчкой.

**6. Как показать аварию?**
Профиль → «Симулировать аварию сервера» → Дневник → потянуть вниз (refresh) → экран ошибки → выключить переключатель → «Повторить» → данные. Mock читает флаг при каждом вызове (`shouldFail`).

**7. Где три состояния?**
Дневник (из модели, `LoadStatus`), Детали сессии (сам грузит `getById` через `FutureBuilder`). Каталог практик и Звуки статичные, своих данных не грузят.

**8. Почему фабрика в `create`?**
`ChangeNotifierProvider(create: (_) => SessionsModel(repo)..load())` — Provider сам создаёт модель один раз и сам вызовет `dispose()`. Если создавать модель в build, она будет пересоздаваться.

**9. Почему `ValueKey(s.id)` в списке?**
При удалении элемента (Dismissible) Flutter сопоставляет виджеты по ключу. Ключ по id, а не по индексу, иначе состояние «съедет» на соседний элемент.

**10. Закрыл приложение — данные пропали. Баг?**
Нет, это контракт L4: mock в памяти, персистентности нет. Сеть — на L5, локальное сохранение — на L6.
